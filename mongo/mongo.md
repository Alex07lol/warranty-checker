## MongoDB — What's happening here

This project uses **MongoDB** as its database with **Mongoose** as the ODM (Object Data Modeling) library for Node.js.

---

### Collections

There are **5 collections**, each mapped to a Mongoose schema:

- **users** — stores account info and notification settings as an embedded subdocument
- **products** — the main collection; each document represents one owned product
- **documents** — metadata only for files (actual files live on Cloudinary)
- **servicehistories** — repair/maintenance logs, each linked to a product
- **notifications** — alert records generated by a cron job

---

### Relationships

MongoDB doesn't have joins, so relationships are handled with **ObjectId references**:

- Every `product` has a `userId` pointing to a `user`
- Every `document` and `serviceHistory` has both a `productId` and `userId`
- Every `notification` has both a `userId` and `productId`

---

### Indexes

Carefully chosen indexes ensure fast queries:

- `email`                                              — unique index for login lookups
- `{userId, isDeleted}`                                — scoped product listing per user
- `{warrantyExpiryDate}`                               — used by the cron job to scan upcoming expiries
- `{isSent, scheduledAt}`                              — cron finds pending notifications to dispatch
- `{userId, productId, notificationType, scheduledAt}` — **unique**, prevents duplicate alerts

---

### Special MongoDB features used
_________________________________________________________________________________________
| Feature                  |                      Where                                  |
|--------------------------|-------------------------------------------------------------|
| **TTL Index**            | `notifications.sentAt` — auto-deletes records after 90 days |
| **Unique Index**         | `documents.publicId`, notification dedup compound key       |
| **Embedded Subdocument** | `notificationPreferences` inside `users`                    |
| **Soft Delete**          | `products.isDeleted` flag instead of actual deletion        |
| **Pre-save Hook**        | Auto-computes `warrantyExpiryDate` before saving a product  |
